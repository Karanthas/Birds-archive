## 1. 产品与使用场景

这是一个部署在个人 NAS 上的私人鸟类摄影相册，仅本人使用，不设应用内登录。主要拍摄地是广东、江苏，也会在其他地区和海外拍摄，所以鸟种查询面向全球。

用户先在其他软件中处理照片，把完成的 JPEG 放入 NAS 指定文件夹，每批通常几十张。系统后台处理，用户稍后集中确认，完成后欣赏照片、找回照片和阅读鸟类介绍。照片安全与审核清楚比处理速度更重要。

**完整首版流程：** 放入文件夹 → 自动导入与识别 → 人工确认或纠正 → 实际移动文件归档 → 摄影相册／鸟种图鉴。

使用电脑与手机浏览器；局域网和远程访问使用同一个私有应用。默认入口为摄影相册，日常导入整理在工作台完成。

## 2. 先设计什么：第一阶段优先交付

请先给出完整首版的信息架构，再优先完成以下第一阶段页面与状态。这一阶段只有导入检查能力，打开后暂时进入导入工作台；摄影相册上线后成为默认入口。

| 第一阶段优先项 | 需要设计的内容 |
|---|---|
| 导入工作台 | 照片预览、任务状态筛选、选中数量、进度与失败重试 |
| 导入照片预览 | 正确方向的大图、文件名、拍摄信息、来源和处理状态 |
| 补充缺失拍摄时间 | 未知状态、输入、保存前核对、成功及冲突反馈 |
| 批量填写地点 | 选择照片、逐张查看旧值与新值、保存结果 |
| 全球鸟种查询 | 中文名／学名搜索、同名区分、名录来源、空结果 |

第一阶段的“待确认”表示导入已完成、等待后续鸟种审核；不展示尚未上线的 AI 候选、归档成功或确认按钮。此时鸟种查询仅供查阅，不会把查询结果关联到照片。

完整首版按以下阶段增加功能，设计稿需标注版本范围，避免把所有控件都放进第一阶段：

| 阶段 | 新增用户能力 |
|---|---|
| 1 | 上述五项导入检查能力 |
| 2 | 手动选种、确认单种／多种、安全归档、基础摄影相册、原图下载 |
| 3 | 自动识别候选、批量审核、识别不可用时的手动处理 |
| 4 | 完整筛选与照片详情、收藏、评分、备注、修正信息、回收与恢复 |
| 5 | 我的鸟种图鉴、有来源的中文介绍、保护状况和相似种区别 |
| 6 | 实际 NAS、局域网、远程访问与备份恢复验收；不新增管理后台页面 |

## 3. 首版网页结构

以下是内容关系，不指定导航放在顶部还是侧边。回收站可以是次级入口；详情与表单不一定占独立页面。

```text
私人相册（直接打开）
   ├─ 摄影相册（默认）
   │  └─ 照片详情／大图浏览
   ├─ 鸟种图鉴（我拍过的鸟种）
   │  └─ 鸟种详情：介绍 + 我的关联照片
   ├─ 导入与审核
   │  ├─ 导入状态与照片预览
   │  ├─ 单张审核／批量审核
   │  ├─ 补充时间／批量填写地点
   │  └─ 全球鸟种查询与选择
   └─ 回收站
      └─ 照片查看与恢复结果
```

### A. 直接打开

- 无账号、密码、登录、退出或会话过期页面。打开地址直接进入默认页。
- 第一阶段默认工作台；第二阶段摄影相册上线后改为相册。
- 网络或表单失败保留当前输入并提示刷新核对，不自动重放修改操作。

### B. 摄影相册

- 以照片为主体，按拍摄时间浏览；未知时间应清楚区分。
- 照片卡片保留必要信息：拍摄时间、已确认鸟种、收藏／评分；信息密度由设计师决定。
- 第四阶段提供鸟种、时间、地点、收藏和星级筛选，显示当前条件、匹配数量和清除入口。
- 打开照片详情；返回时保留筛选与浏览位置。可从鸟种标签进入该种照片或图鉴。
- 首次无归档照片：引导去导入与审核；筛选无结果：保留条件并允许清除。两种空态要区分。

### C. 照片详情／大图浏览

- 大图为主体，可查看完整构图与识别所需细节；不把卡片裁剪结果当作完整照片。
- 信息：文件名、已确认的一个或多个鸟种、拍摄时间与地点、收藏、1–5 星或未评分、备注。
- 操作按阶段出现：下载原图；收藏／取消、评分／清除、添加／编辑／清除备注、修改时间地点或鸟种、移入回收站。
- 时间地点能区分“从照片读取”与“人工补充／修正”。只有日期时保留日期精度，不补造时刻或时区。
- 上一张／下一张在当前浏览集合内切换，例如当前筛选结果或某鸟种的照片；首尾边界清楚。
- 导入预览复用大图体验，但第一阶段只提供读取信息、补缺失时间与导入状态，不提前提供完整管理操作。

### D. 导入与审核工作台

- 内容：照片预览、文件名、时间地点、当前处理状态、选中数量、可执行操作。
- 支持按待处理、处理中、待确认、失败等状态查看；重复导入另行标记并关联已有照片。
- 后台可慢慢处理；显示实际步骤、最近更新时间与失败原因。不使用没有依据的进度百分比或倒计时。
- 用户可离开页面稍后回来。自动刷新不能清空正在填写的内容、选择或抢走焦点。
- 点击一张照片进入预览／审核；批量操作之前显示选中的确切对象和影响。选择是否跨页必须明确，不默默扩大范围。
- 空态说明将 JPEG 放入已配置文件夹；浏览器上传按钮不属于本次需求。

### E. 单张审核与批量审核

- 单张审核同时看清照片、按顺序排列的候选和拟确认鸟种。候选显示可获得的中文名、学名与识别来源。
- 可接受候选、搜索更换、添加漏识别的鸟种、移除误选项，或保持待确认稍后处理。
- “机器建议”和“人工已确认”清楚分开；模型分数不可写成未经验证的“准确率”。
- 未配置识别或识别失败时，仍可搜索鸟种手动确认；重跑识别不能覆盖已有人工结论。
- 批量审核必须区分两种操作：**确认每张各自的候选**；**把选中照片统一设置为指定鸟种集合**。
- 提交前逐张列出原状态与将确认的结果。统一设置时说明是替换为所列集合，避免意外丢掉多鸟种关联。
- 有无法处理或已变化的照片时，指出具体对象与原因，让用户核对；不能把部分结果概括成整批成功。
- 确认提交后进入归档处理中；只有实际移动完成才显示“已归档”。

### F. 拍摄信息表单

- 第一阶段：为选中的导入照片批量填写地点；为没有可靠时间的照片补充时间，也可以继续保留未知。
- 批量地点预览每张照片的旧值、新值及总数量；已填写不同地点时不能静默覆盖。
- 第四阶段：修改已有时间地点。展示原始读取值、当前人工值与本次修改，保存后仍可辨别来源。
- 设计输入错误、保存中、成功、网络失败、照片已被其他操作改变等状态；失败保留可核对的草稿。
- 修改已归档照片的年份可能触发目录迁移，应先说明影响，再呈现迁移结果。

### G. 全球鸟种查询／选择

- 中文名或学名搜索；常见拍摄地区不限制全球结果。
- 结果显示中文名（若有）、学名、名录来源／版本；同中文名物种必须可区分，中文名缺失时以学名显示。
- 第一阶段为只读查询；第二阶段起在审核情境中支持选中一个或多个鸟种。
- 设计尚未搜索、搜索中、无匹配、名录暂不可用等状态。
- 此处查询“可选的全球鸟种”，与图鉴中的“我已经拍过的鸟种”范围不同。

### H. 我的鸟种图鉴与鸟种详情

- 图鉴列表：已拍鸟种的照片封面、中文名、学名和照片数量；支持中文名／学名搜索。
- 鸟种详情：名称、外形、习性、分布、保护状况、相似鸟种及区别、资料来源和资料日期、我的关联照片。
- 保护状况分别标明全球受威胁等级与国家／地区法定保护名录，不合并成一个含混的“保护等级”。
- 相似种区别采用有来源的可见辨别特征；资料中的相似种未必是用户拍过的鸟种，不伪造其个人照片。
- 资料暂缺、部分字段缺失、加载失败各有提示；未知保护状况不能显示成“无保护”。
- 已允许缓存的资料在外网暂不可用时仍可阅读，显示资料时间；更新失败可重试，照片浏览与归档继续可用。

### I. 回收站

- 列出已移入回收站的照片，提供查看与恢复入口；保留鸟种和个人整理信息供辨认。
- 移入前说明照片将从正常相册及鸟种计数中移除，原图和信息仍保留。
- 恢复后照片、收藏、评分、备注、时间地点与鸟种关联一起回来。
- 原位置已占用时，不覆盖其他照片；恢复结果显示实际位置，冲突或失败给出可理解的后续动作。
- 首版不设计永久删除、自动清空或定期清理功能；回收站为空也有明确状态。

## 4. 关键流程和必须保留的行为

### 导入到浏览

1. 用户把照片放入文件夹，工作台显示发现、等待完整写入、处理和可查看状态。
2. 用户检查照片，补地点或缺失时间，查看候选或手动搜索鸟种。
3. 用户明确确认一个或多个鸟种；不确定的照片留待确认，不触发归档。
4. 页面显示归档处理中；失败、中断或待恢复时不能提前宣布成功。
5. 完成后进入摄影相册，并可从对应鸟种找到照片、下载原图。

### 真实目录与多鸟种

以下为路径结构示意，不是真实 NAS 路径：

```text
单鸟种：鸟类归档/{鸟种目录名}/{拍摄年份}/照片.jpg
多鸟种：鸟类归档/多鸟种/{拍摄年份}/照片.jpg
未知时间：以上年份位置使用“未知年份”
```

多鸟种照片在磁盘只保留一份受管理的原图，在各个已确认鸟种页面均可见；相册总数仍只算一张。不同鸟种页的数量可以包含同一张照片，不能直接相加作为总照片数。

目录冲突不覆盖其他照片。所有整理操作均保留原 JPEG 字节，用户补充的信息单独保存；下载的原图也保持原样。

### 更正、回收与恢复

更正鸟种或年份 → 核对旧值、新值及目录影响 → 保存／迁移中 → 完成或可恢复错误。人工确认与文件归档是两件事，状态必须分别表达。

移入回收站 → 从正常浏览与鸟种计数移除 → 在回收站查看 → 恢复 → 返回正常浏览。冲突时说明最终恢复位置，不把“已提交恢复”当作“已恢复”。

## 5. 需要出设计稿的状态

| 情境 | 用户应看到／能做什么 |
|---|---|
| 加载、预览生成、保存中 | 当前正在做什么；避免重复提交，保留页面稳定性 |
| 首次无照片／筛选为空／搜索无匹配 | 区分原因，给出对应入口或清除条件 |
| 导入／识别／归档失败 | 具体、无敏感信息的原因；可重试或明确待修复条件 |
| 重试已提交 | “已加入重试队列”，不是“已完成”；显示后续真实进度 |
| 重复文件 | 关联已有照片，说明导入文件保留；不生成第二张资产或反复弹窗 |
| 同名不同照片 | 都能被辨认和保留；文件名相同不等于内容重复 |
| 原图当前不可用 | 明确提示；已有预览不代表原图可下载，不假报下载成功 |
| 拍摄时间／地点未知 | 显示未知并提供适用的补充入口，不猜测时间或地点 |
| 无中文名／图鉴资料部分缺失 | 学名回退或逐项标记暂缺；其余可用内容正常展示 |
| 状态长时间未更新／网络中断 | 保留最后更新时间和刷新入口，不擅自判定失败或完成 |
| 请求校验失败 | 简短原因与刷新入口，不跳登录，不自动重复上次修改 |
| 保存时对象已变化 | 指出冲突，保留草稿并要求重新核对，避免覆盖新结果 |

## 6. 设计原则与边界

- 摄影相册以欣赏照片为主，审核工作台以看清结果和快速操作为主；两种密度可以不同。
- 手机端能查看大图、选鸟种、核对批量影响和填写表单；不要依靠悬停才能读取完整信息。
- 长文件名、长学名、多鸟种标签、竖幅／横幅照片和长备注均需适配；状态除颜色外也应有文字。
- 保证键盘操作、明确焦点、可读标签和触摸目标；错误反馈靠近对应字段或照片。
- NAS 还承担存储任务，页面使用预览图按需加载；处理慢时仍能浏览，不一次载入全部原图。
- 不设应用登录，页面与图片直接使用；保留CSRF、Host、no-store及安全媒体路径。网络可达范围在部署入口控制，远程入口不自动等于公开分享。
- 本地还是云端识别尚未选定，设计不能承诺实时速度、识别准确率或默认照片已获云上传授权。
- 首版不含公开分享、多人管理、社交、地图统计、照片编辑、RAW／视频、原生 App 或浏览器上传。
- 部署、模型评测与备份以相应配置和文档解决；本次不额外要求设置控制台或评测仪表盘。

### 6.1 文字减量方向（收到设计稿后的补充）

**用户确定的偏好：照片优先，界面文字尽可能少。** 以下是据此提出的落地建议；减少默认可见的说明，不删功能或必要反馈，也不靠缩小字号隐藏文字。鸟类介绍、相似种区别和用户备注属于阅读内容，不因精简 UI 而取消。

- 删除正式产品中的英文装饰副标题、重复页面标题、宣传语和 P1／P4 等开发阶段标记。原型演示说明保留在交付文档或独立演示标识中；有示意素材的原型不能去掉标识后冒充真实资料。
- 常态页面不常驻整段操作教学。首次使用、用户点开帮助或发生对应异常时，才显示必要的一句说明。
- 相册卡片以照片和鸟名为主；日期可用分组表达，地点、完整时间、文件名等放进详情。收藏与评分使用紧凑图标；多鸟种关系、无中文名时的学名回退仍可读取。
- 工作台保留辨认照片所需信息、简短状态和下一步；选中后再显示批量工具栏。选择范围使用“本页 9 张”等短标签，不能为省字隐藏实际作用对象。
- 收藏、放大、切图等常见动作可用图标，但需可访问名称及可发现的提示。确认、统一替换、恢复等易混淆动作保留短文字，不仅靠图标或颜色表达。
- 文件路径、读取来源、名录版本等放入“详情／来源”区域；发生目录变更或恢复冲突时，在核对与结果中呈现相关位置。鸟种资料来源与日期保持可查，保护体系不合并。
- “待确认”“归档中”“已归档”“失败”等状态仍明确区分。错误用“发生什么 + 可做什么”的短句；批量变化、覆盖影响与冲突不能被折叠到提交后才发现。

| 设计稿位置 | 建议的精简方式 |
|---|---|

## 7. 请设计师交付
